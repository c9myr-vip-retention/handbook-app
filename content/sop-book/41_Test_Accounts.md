## Procedure

| Step no. | Step name | Specific action | Operating standard | Tools / forms used | Points to note |
|---|---|---|---|---|---|
| 1 | Create account | Create the account on the brand site. The username starts with "test" followed by the staff name, for example testaldo. | Username always starts with "test" | Brand site / BO | "test" at the front makes the account easy to spot in any list |
| 2 | Tag the account (TC) | In the BO, open the test account's Player Information. Set Internal Level = Test Account. Set Operational Label = Staff Account. Save. | Both fields set before first use | TC BO | An untagged account counts as a real player in reports |
| 3 | Tag the account (Zyra) | In the BO, open the test account's User Information. Set User Tag = Test Account. Save. | Tag set before first use | Zyra BO | An untagged account counts as a real player in reports |
| 4 | Register the account | Add the account to the Test Account Register: brand, username/UID, holder, purpose, created date, tag done. | Register updated the same day | Lark sheet | Never record the password in the register |
| 5 | Use only for checks | Use the account only for checks, for example game access checks, maintenance checks, promotion or widget tests. | No real-money play; no bonus claims | Brand site | See Chat SOP Case Library for game access checks |
| 6 | Monthly check | On the 2nd of each month, ATL checks: every registered account is tagged in the BO; no account is used by staff who left the team; no "test..." username in the BO is missing from the register. | 5-minute check, done on the 2nd (downgrade day) | Lark sheet; BO | Untagged or unregistered test accounts enter the pool and inflate contact and reactivation figures |
| 7 | Close an account | When no longer needed, ask the brand to deactivate it and mark it Closed in the register. | Closed the same week it stops being needed | BO; Lark sheet | OPEN: who deactivates (TL, IT or brand) |

## 1. Objective
Control every test account so it is created on request, tagged in the back office before first use, recorded in one register, used only for checks, and closed when no longer needed. Tagging keeps test accounts out of player reports, retention figures and campaigns.

## 2. Scope
All test accounts used by VIP Retention on every brand, TC Gaming and Zyra Gaming. Covers creation, tagging, registration, use, review and closure. It does not cover real player accounts or staff BO logins.

## 3. Golden Rules
- Tag before first use. An untagged test account is treated as a real player in every report.
- Never deposit real money, claim a bonus or join a campaign with a test account.
- Never share or write down a test account password in chat, Lark docs or this register.
- One register for all test accounts. If it is not in the register, it should not exist.
- Test accounts are never counted in KPI, retention, reactivation or engagement figures.

## 4. Remarks
- OPEN: limit per brand or per team.
- OPEN: who deactivates a closed account and how.
- OPEN: where test account passwords are held (password manager or BO reset only).
- Check that the VVIP Tracker console excludes accounts tagged Test Account, so they never enter the pool or contact lists.
